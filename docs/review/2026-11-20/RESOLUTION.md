# Resolution of the 2026-11-20 review

The review in `REPORT.md` was run by an independent agent from `docs/review/antigravity-review-prompt.md`, overseen by
the author. Every finding is listed here with what was done and the test that holds it in place. Tests named
`test_...` are in `tests/test_review_fixes.py` unless another file is given.

| Finding | Severity | Status | Change | Held by |
| --- | --- | --- | --- | --- |
| F2.1 / F3.1 differing runtime errors compared as equal | Critical | Fixed | `cases.compare`: when both programs stop with an error, only the runtime's own `CobolError` counts as the same stop. Any other Python exception is a difference, so gap filling cannot save it either. | `test_a_python_crash_is_not_the_same_as_the_cobol_stopping` |
| F8.1 no test for two differing errors | High | Fixed | The test above. | |
| F1.1 UNSTRING pointer below 1 | High | Fixed | `rt.unstring`: a pointer outside the sending field is an overflow and nothing moves, as in GnuCOBOL. | `test_unstring_pointer_outside_the_item_overflows` (against GnuCOBOL) |
| F1.2 text with a sign moved to a number | High | Fixed | `rt._alpha_to_number` follows libcob: blanks, one sign, digits with one decimal point; anything else gives zero. | `test_text_to_number_follows_libcob` (against GnuCOBOL), `test_text_to_number_unit` |
| F1.3 INSPECT on a signed number lost the sign | High | Fixed | INSPECT works on the stored characters of a DISPLAY number, sign included. | `test_inspect_on_signed_numbers_keeps_the_sign` (against GnuCOBOL) |
| F2.2 binary records split at 0x0A and 0x0C | High | Fixed | `cases.text_only`: only records made entirely of text or DISPLAY digits are treated as print files. | `test_a_line_feed_byte_in_a_packed_record_is_data`, `test_a_print_file_still_splits_at_its_line_and_page_breaks` |
| F2.4 / F8.3 exported suite accepted any exception | High | Fixed | The exported suite expects `CobolError` and keeps binary records whole. | `test_the_exported_suite_is_strict_and_keeps_binary_records_whole`, `test_the_exported_suite_passes_on_its_own` |
| F6.1 write-up has open questions | High | Partly | Two of the questions are answered. Three ask about the author's own sessions and are left for the author. `scripts/check_rules.py` warns until they are filled in. | `scripts/check_rules.py` |
| F2.3 receipt ignored copybooks and called programs | Medium | Fixed | `report.source_sha` hashes the main source with every copybook and called program beside it. A one-file program keeps its old hash. | `test_the_receipt_changes_when_a_copybook_changes` |
| F3.2 equivalence and branches gated by a code | Medium | Mitigated | The search now varies text fields (record types, codes) as well as numbers, and its default budget is 2,000 evaluations. No test builds a gated branch, so this is a reduced risk, not a proof. "Likely equivalent" stays worded as a likelihood. | `tests/test_gapfill.py` |
| F5.1 dialogs did not return focus | Medium | Fixed | Every dialog returns focus to the control that opened it. | `scripts/ui_check.py`: "focus returns to the search button" |
| F8.2 no tests for UNSTRING pointers and INSPECT signs | Medium | Fixed | The tests for F1.1 and F1.3. | |
| F1.4 DIVIDE ... REMAINDER without GIVING | Low | Fixed | Reported as a statement that needs a person, instead of emitting invalid Python. | `test_divide_remainder_without_giving_is_reported` |
| F3.3 arithmetic mutations never judged equivalent | Low | By design | Reaching changed arithmetic without a changed output says too little, so these stay "needs human review". Written down in `.kiro/specs/seance/design.md`. | |
| F4.1 IPv6 loopback refused | Low | Fixed | Requests to `[::1]` are answered; other host names are still refused. | `test_ipv6_loopback_is_accepted` |
| F5.2 some dialogs had no initial focus | Low | Fixed | Opening a dialog focuses its first field or its main button. | `scripts/ui_check.py` checks the command bar; the others share the same code |
| F7.1 SEANCE_HOST and SEANCE_PORT undocumented | Low | Fixed | Documented in the README under Settings. | |
| F6.2 MCP settings hold the author's path | Note | Tooling added | `python -m seance setup --mcp-config` writes this folder's paths into `.kiro/settings/mcp.json` and keeps other settings, and `seance doctor` warns when the paths in it do not exist. The committed file is regenerated by the author, because Kiro does not let an agent edit `.kiro/settings`. | `tests/test_release.py::test_mcp_settings_keep_what_else_is_there` |
