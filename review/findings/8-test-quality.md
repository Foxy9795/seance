### F8.1 Missing test coverage for differing runtime errors between COBOL and Python
Severity: High
Confidence: verified
Where: tests/test_pipeline.py:51
What happens: `test_python_crash_is_reported_not_raised` in `tests/test_pipeline.py` verifies that when COBOL exits normally and Python raises an exception (`ZeroDivisionError`), a difference is recorded. However, no test in the test suite verifies what happens when COBOL raises an error and Python raises an error. Because of this gap, the critical bug in `compare()` (F2.1) where differing error messages return zero diffs and declare "Spirit matched" went completely undetected by all 161 tests.
Evidence: Read `tests/test_pipeline.py` lines 51-56:
```python
@needs_cobol
def test_python_crash_is_reported_not_raised():
    report = verify("loan", "migrated.loan_naive", 5)
    assert not report.matched
    assert any("ZeroDivisionError" in (s["python_error"] or "") for s in report.sets)
```
Notice `expected.error` in this case was `None`. No test supplies two results where both have non-None `error` with different messages.
Why it matters: Critical proof integrity bugs can exist in production while the entire test suite reports 100% pass.
Suggested fix: Add a unit test in `tests/test_pipeline.py` or `tests/test_features.py` testing `compare()` with mismatched errors and asserting that a `Diff("run", -1, ...)` is generated.

### F8.2 Unchecked corner cases in UNSTRING pointer boundaries and INSPECT sign handling
Severity: Medium
Confidence: verified
Where: tests/test_codec_vs_cobol.py:1
What happens: The differential test suite checks numeric formatting (`test_numbers_vs_cobol.py`) and stress translation (`test_translator_stress.py`), but lacks differential tests for:
1. `UNSTRING` with `pointer <= 0` or `pointer > len(src)` (misses OVERFLOW, corrupts target via negative slice).
2. `MOVE` of alphanumeric strings containing a leading sign (`"-123"`) to numeric items (silently drops sign and stores zero).
3. `INSPECT REPLACING` on signed numeric fields (silently drops negative sign).
Evidence: Search of `tests/` shows zero tests verifying `UNSTRING WITH POINTER` out-of-bounds conditions, or `INSPECT` on signed `PIC S9(n)` display items.
Why it matters: Without regression tests, translator runtime divergences from GnuCOBOL semantics remain invisible.
Suggested fix: Add differential test cases in `tests/test_codec_vs_cobol.py` and `tests/test_numbers_vs_cobol.py` covering UNSTRING pointer bounds and signed INSPECT.

### F8.3 Standalone exported test suite passes unconditionally on any exception
Severity: High
Confidence: verified
Where: seance/export.py:94
What happens: In the exported test suite template generated by `export.py`, lines 94-96 assert:
```python
if meta.get("error"):
    with pytest.raises(Exception):
        program.main(IO(files, meta["stdin"]))
    return
```
Because it catches bare `Exception`, any catastrophic error (e.g. `ImportError`, `AttributeError`, `SyntaxError`, or initialization crash) causes the test to pass.
Evidence: Read `seance/export.py` lines 93-96.
Why it matters: A customer running `python -m pytest tests` on an exported migration package will see green passing tests for error fixtures even if their code has completely broken imports or unintended crashes.
Suggested fix: Store `meta["error_type"]` and assert `with pytest.raises(CobolError):` or match the specific error message.
